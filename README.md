# 🧠 ИИ-агент поверх локальной нейросети (v1.0 → v4.3)

Локальная LLM (Ollama + Qwen) управляет компьютером с Ubuntu: пишет
shell-команды, читает вывод, видит интерфейс, нажимает кнопки, помнит уроки
и — в режиме потока — сама решает, чем заняться дальше.
**Ноль зависимостей**: только Python 3 и работающий Ollama. Работает на
слабом железе: от 3–4 ГБ RAM в виртуальной машине.

```
[шаг 1] АГЕНТ -> ПК: {"open": "firefox"}
          ПК -> АГЕНТ: ФАКТ: «firefox» запущен и окно АКТИВНО
[шаг 2] АГЕНТ -> ПК: {"scan": ""}
          ПК -> АГЕНТ: КНОПКА [ 71, 259] «Background»  ...
[ГОТОВО за 4 шаг(ов)] Firefox открыт, нужная кнопка найдена и нажата
```

**Философия проекта:** маленькой локальной модели не хватает ума —
добавь ей органов чувств, памяти и правил, а не параметров.

Полная история изменений — [CHANGELOG.md](CHANGELOG.md).

## Как это работает

Модель общается строгим JSON-протоколом, одно действие за шаг
(`{"command": ...}` → ПК выполняет → вывод возвращается модели). Слабые
модели (1.5B–3B) склонны **галлюцинировать успех**, поэтому протокол требует
доказывать всё фактами (`pgrep`, `ls`, координаты из сонара), а не словами.

## Требования

- Ubuntu (разработано на 24.04), Python 3, [Ollama](https://ollama.com)
- Модель-мозг: любая инструктивная ~1.5B–3B (рекомендуем qwen2.5:3b)

| Конфигурация | RAM под модель | Минимум в машине |
|---|---|---|
| мозг 1.5B | ~1.5 ГБ | 3 ГБ |
| мозг 3B | ~2.6 ГБ | 4–5 ГБ |
| мозг + глаза (v4.0, параллельно) | ~6 ГБ | 8 ГБ |
| мозг + глаза (v4.1+, поочерёдно) | ~2.6 ГБ | 4 ГБ |

## Установка с нуля

### 1. Ollama

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

(вручную, если скрипт недоступен: релиз `ollama-linux-amd64` со страницы
https://github.com/ollama/ollama/releases → распаковать в `/usr/local`.)

### 2. Мозг

```bash
ollama pull qwen2.5:3b          # простой путь
```

или свой GGUF:

```bash
mkdir -p ~/brain && cd ~/brain      # положите сюда qwen2.5-3b-instruct-q4_k_m.gguf
echo "FROM ./qwen2.5-3b-instruct-q4_k_m.gguf" > Modelfile
ollama create mybrain -f Modelfile
ollama list                          # проверка
```

Слабая машина? Возьмите 1.5B: `ollama pull qwen2.5:1.5b`.

### 3. Сервер (всегда, отдельный терминал)

```bash
ollama serve
```

### 4. Для GUI-версий (v3.1 и новее)

```bash
sudo apt install -y xdotool gnome-screenshot
echo $XDG_SESSION_TYPE     # нужно: x11
```

Если `wayland`: на экране входа кликнуть пользователя → шестерёнка ⚙ →
**«Ubuntu on Xorg»** → пароль. Запоминается навсегда.

### v1.0 — «Мозг и руки»

```bash
python3 agent_ollama.py "покажи версию ядра и количество ядер"
python3 agent_ollama.py "создай файл /tmp/note.txt с датой и покажи его"
AGENT_MODEL=mybrain python3 agent_ollama.py "..."
```

Разовая задача из аргумента. Политика **DENY**: `rm -rf`, `sudo`, `dd`,
`shutdown` и т. п. не выполняются, даже если их придумала нейросеть.

### v2.0 — память и автономия

```bash
python3 agent_v2.py
Вы > создай файл hello.txt на рабочем столе     # задача
Вы > /free 5                                     # автономия: сама придумывает цели
Вы > /memo                                       # дневник
Вы > /exit                                       # выход (память остаётся)
```

После каждой задачи модель пишет себе **урок** в `~/agent_notes.txt`,
последние ~15 попадают в системный промпт — память переживает перезапуск.
Журнал эпизодов — `~/agent_diary.md`. `CONFIRM=1` — одобрение команд вручную.

### v2.1 — нервы из стали

Мусор `Gtk-Message` / `Not loading module atk-bridge` не доходит до модели
(не пугает её). Третья одинаковая команда блокируется с приказом проверить
факты и завершить. Успех — по фактам, а не по страшным словам.

### v3.0 — живой поток

`/free N` — непрерывная цепочка связанных этапов (не хаотичные прыжки).
Сервер недоступен — 3 переподключения вместо падения. До 5 переспросов при
сломе формата; «не сдаваться, пока не испробованы 3 разных способа».

### v3.1 «КНОПКОДАВ» — первые GUI-руки

```bash
sudo apt install -y xdotool python3-dogtail    # dogtail — опционально
```

Знает панели Настроек (`gnome-control-center background|appearance|wifi|...`),
обои через `gsettings`, скриншоты, паттерн «запустил → pgrep → done».
Стратегия: CLI/клавиатура раньше голых координат.

### v4.0 «ГЛАЗА» — видит экран (8+ ГБ)

Два мозга: планировщик + зрительная (Qwen2.5-VL-3B: файл `qwen2.5-vl-3b-instruct-q4_k_m.gguf`
+ `mmproj-...f16.gguf` из репозитория `Qwen/Qwen2.5-VL-3B-Instruct-GGUF`,
далее `ollama create eyes -f Modelfile`).

```bash
AGENT_MODEL=mybrain AGENT_VISION=eyes python3 agent_v4.py
EYE=always ... python3 agent_v4.py    # автовзгляд после каждого шага (медленно)
```

Действия: `{"see": "вопрос"}`, `{"click": [x, y]}`. Правило: see → click →
see-again. Глаза ошибаются на ±50 px. Без модели `eyes` сама деградирует до v3.1.

### v4.1 «СОНАР» — зрение без нейросети 📡 (4 ГБ!)

GNOME и так знает все свои кнопки — через дерево доступности **AT-SPI**.
Скрипт `uitree.py` печатает видимые элементы с **точными** координатами
центров: память ~0, ошибки координат нет.

```bash
sudo apt install -y python3-pyatspi
gsettings set org.gnome.desktop.interface toolkit-accessibility true
reboot                               # один раз
python3 uitree.py                    # проверка: список КНОПКА [x,y] «...»
python3 uitree.py Settings           # только окна со словом
python3 agent_v4_1.py
```

`{"scan": ""}` — посмотреть экран текстом; координаты для `{"click"}` брать
из сонара. `SCAN=always` — автоскан после каждого действия.
Опциональные глаза (напр. Qwen2-VL-2B) работают даже в 4 ГБ: агент выгружает
мозг на время взгляда (`ollama stop` + `keep_alive: 0`).

### v4.2 «ОТКРЫВАШКА» — надёжный запуск программ 🔧

Snap-программы просыпаются 20–60 с: `pgrep` сразу — пустой, модель паниковала
и шла промахиваться по иконкам дока. Теперь запуск — детерминированное
действие лаунчера, а не импровизация:

```json
{"open": "firefox"}   — установлен? → запустить → ЖДЁТ до 45 с → окно → ФАКТ
{"wait": 10}          — пауза 1–30 с (прогрузка окна/сайта)
```

Псевдонимы: `firefox/браузер`, `терминал/консоль/cmd`, `файлы/проводник`,
`настройки/settings`, `блокнот/текст`, `калькулятор`, `магазин`, `хром`.
Нет программы — честное «НЕ УСТАНОВЛЕНА (это факт)». Правило: иконки дока
для запуска не кликать вообще.

### v4.3 «ТЕЧЕНИЕ» — поток, который пишет сам мозг 🌊

Раньше аварийным запасом в `/free` был случайный выбор из 4–5 заготовок —
поток выглядел как «те же промпты по кругу». Теперь генератор целей — настоящий:

- перед выбором цели агент смотрит **снимок мира** (окна на экране, итог
  прошлого этапа, свои уроки)
- **анти-повтор**: цели из дневника и сессии запрещены; похожая на 55+%
  отбрасывается, модель передумывает (до 3 попыток)
- серия провалов → принудительная смена области деятельности
- аварийная цель — не случайная, а из **реального активного окна**
- `/free` без числа = **бесконечный поток** до Ctrl+C; с числом — кап

## Полный протокол действий (v4.3)

| JSON | Что делает |
|---|---|
| `{"command": "..."}` | shell-команда (DENY-политика + фильтр шума) |
| `{"scan": ""}` / `{"scan": "Settings"}` | сонар: элементы экрана с точными координатами |
| `{"click": [x, y]}` | клик (координаты — только из сонара) |
| `{"open": "firefox"}` | запуск с ожиданием и факт-проверкой |
| `{"wait": 10}` | пауза 1–30 с |
| `{"see": "..."}` | глаза (если `AGENT_VISION` задан) |
| `{"done": "..."}` | задача завершена (только по факту) |

Рабочий цикл с GUI: **scan → click → scan (проверка)**.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AGENT_MODEL` | `mybrain` | текстовый мозг |
| `AGENT_VISION` | *(пусто = глаза выкл)* | зрительная модель |
| `AGENT_UITREE` | `~/uitree.py` | путь к сонару |
| `SCAN=always` | выкл | автоскан после каждого действия |
| `EYE_SWAP=0` | выгружает | не выгружать мозг на время взгляда |
| `CONFIRM=1` | выкл | одобрение каждого действия `[y/n]` |

## Команды внутри агента

`любая фраза` — задача · `/free [N]` — поток (без N — до Ctrl+C) ·
`/memo` — дневник · `/exit` — выход

Файлы памяти: `~/agent_diary.md` (журнал), `~/agent_notes.txt` (уроки).

## Включение настоящих глаз (опционально, v4.1+)

```bash
cd ~/brain
# скачайте из huggingface.co/bartowski/Qwen2-VL-2B-Instruct-GGUF два файла:
#   Qwen2-VL-2B-Instruct-Q4_K_M.gguf  и  mmproj-Qwen2-VL-2B-Instruct-f16.gguf
printf 'FROM ./Qwen2-VL-2B-Instruct-Q4_K_M.gguf\n' > Modelfile-eyes
ollama create eyes -f Modelfile-eyes
ollama list                           # проверка: есть eyes
AGENT_VISION=eyes python3 agent_v4_3.py
```

Тест без агента:
`gnome-screenshot -f /tmp/t.png && ollama run eyes "Что на изображении?" /tmp/t.png`

Разделение труда: сонар — кнопки и координаты (бесплатно, точно), глаза —
содержимое картинок (медленно, неточно ±50 px).

## Безопасность ⚠️

- DENY-лист — не песочница. Запускайте в ВМ (VirtualBox) со снапшотами.
- Первые запуски — с `CONFIRM=1`. Автономию останавливает `Ctrl+C` / `/exit`;
  после перезапуска агент пассивен.
- `/free` без числа теперь бесконечен — держите `Ctrl+C` под рукой. 🙂

## Диагностика

| Симптом | Лечение |
|---|---|
| `ConnectionRefusedError [Errno 111]` | `ollama serve` в отдельном терминале |
| `model 'mybrain' not found` | `ollama list`; пересоздать через `ollama create` |
| клики не работают | сеанс Wayland → «Ubuntu on Xorg» через шестерёнку |
| «сонар почти ничего не видит» | accessibility выключена → `gsettings set org.gnome.desktop.interface toolkit-accessibility true` + reboot |
| предупреждение про pyatspi | `sudo apt install -y python3-pyatspi` |
| `open`: «НЕ УСТАНОВЛЕНА» | факт: программы нет → `ls /usr/share/applications`, `snap list` |
| `open` долго «думает» | норма: snap-программы просыпаются до 60 с |
| поток повторяет цели | это лечит v4.3 (анти-повтор) |
| машина виснет | мозг поменьше (1.5b), `zram-config`, меньше окон; на хосте — закрыть лишнее |
