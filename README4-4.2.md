# ИИ-агент поверх локальной нейросети — Часть 2: GUI-эпоха (4.0 → 4.2)

От «видит экран нейросетью» к «видит интерфейс **без** нейросети» и
надёжным рукам. Базовая установка (Ollama, мозг, `ollama serve`) — в
[README1-4.md](README1-4.md).

Эволюция этой части:

| Файл | Версия | Суть | RAM |
|---|---|---|---|
| `agent_v4.py` | 4.0 «ГЛАЗА» | `{"see"}` (скриншот→зрительная модель) + `{"click":[x,y]}` | 8+ ГБ |
| `agent_v4_1.py` + `uitree.py` | 4.1 «СОНАР» | зрение через дерево доступности AT-SPI, **без нейросети** | **4 ГБ** |
| `agent_v4_2.py` + `uitree.py` | 4.2 «ОТКРЫВАШКА» | + детерминированный `{"open"}` и пауза `{"wait"}` | **4 ГБ** |

## Общие требования GUI-версий

```bash
sudo apt install -y xdotool gnome-screenshot
echo $XDG_SESSION_TYPE     # нужно: x11
```

Если `wayland`: на экране входа кликнуть пользователя → шестерёнка ⚙ →
**«Ubuntu on Xorg»** → ввести пароль. Запоминается навсегда. (На Wayland
xdotool не может «тыкать» в чужие окна — это осознанное ограничение Wayland.)

## v4.0 «ГЛАЗА» (8+ ГБ)

См. [README1-4.md](README1-4.md#v4-0-глаза--видит-экран). Два мозга
одновременно: планировщик + Qwen2.5-VL. Работает, но тяжело — поэтому
появилась v4.1.

## v4.1 «СОНАР» — зрение без нейросети 📡

**Идея:** слабой модели не нужна нейросеть-зрение для кнопок. GNOME и так
знает про все свои элементы — через дерево доступности **AT-SPI** (та самая
`atk-bridge`, из-за которой версия 2.0 пугалась `Gtk-Message`). Скрипт
`uitree.py` читает это дерево и печатает все видимые кнопки/меню/поля
с **точными** координатами центров. Память — почти ноль, ошибок координат — ноль
(у глаз было ±50 px).

### Установка (один раз)

```bash
sudo apt install -y python3-pyatspi
gsettings set org.gnome.desktop.interface toolkit-accessibility true
reboot                                    # один раз, чтобы приложения подхватили accessibility
```

Положите `uitree.py` рядом с агентом в домашнюю папку.

### Проверка сонара руками

Откройте, например, Settings и выполните:

```bash
python3 uitree.py              # весь экран
python3 uitree.py Settings     # только окна со словом в названии
```

Ожидаемый вывод:

```
АКТИВНОЕ ОКНО: «Settings»
--- ОКНО «Settings» (gnome-control-center) ---
КНОПКА         [  71, 259]  «Background»
КНОПКА         [  71, 324]  «Appearance»
ПОЛЕ-ВВОДА     [ 183,  67]  «Search»
```

### Запуск

```bash
python3 agent_v4_1.py
SCAN=always python3 agent_v4_1.py    # + автоскан после каждого действия
```

При старте агент сам докладывает: `Сонар: ОК (pyatspi на месте) 📡`,
список моделей и тип сеанса.

### Опционально: настоящие глаза даже в 4 ГБ

Если нужно ещё и *описывать картинки*: маленькая зрительная модель
(**Qwen2-VL-2B**, репозиторий `bartowski/Qwen2-VL-2B-Instruct-GGUF`,
файлы `Qwen2-VL-2B-Instruct-Q4_K_M.gguf` + `mmproj-...f16`.gguf, далее
`ollama create eyes -f Modelfile` как в v4.0). Агент сам **выгружает мозг**
на время взгляда (`ollama stop`) и выгружает глаза сразу после
(`keep_alive: 0`) — обе модели никогда не занимают память одновременно.
Цена: 20–60 с на взгляд. Отключить выгрузку: `EYE_SWAP=0`.

```bash
AGENT_VISION=eyes python3 agent_v4_1.py
```

## v4.2 «ОТКРЫВАШКА» — надёжный запуск программ 🔧

**Проблема v4.1:** «открой firefox» модель делала как хотела. Firefox —
snap-пакет, просыпается 20–60 с; `pgrep` сразу после запуска пуст → модель
паниковала и шла кликать иконки дока (и промахивалась в соседний значок).

**Решение:** запуск — больше не импровизация модели, а детерминированное
действие лаунчера:

```json
{"open": "firefox"}   — проверит, что установлен → запустит → ЖДЁТ до 45 с →
                        найдёт окно, активирует → доложит только ФАКТЫ
{"wait": 10}          — пауза 1–30 с (дождаться прогрузки окна/сайта)
```

Псевдонимы из коробки: `firefox/браузер`, `терминал/консоль/cmd`,
`файлы/проводник/files`, `настройки/settings`, `блокнот/текст/editor`,
`калькулятор`, `магазин`, `хром/chrome`. Неизвестное имя — честный ответ
«НЕ УСТАНОВЛЕНА (это факт)» вместо галлюцинации. Инъекции отсекаются
(имя — одно слово).

Запуск — просто новая версия файла (память-дневники общие и сохраняются):

```bash
python3 agent_v4_2.py
```

## Полный протокол действий (v4.2)

| JSON | Что делает |
|---|---|
| `{"command": "..."}` | shell-команда (с DENY-политикой и фильтром шума) |
| `{"scan": ""}` | сонар: все видимые элементы экрана с координатами |
| `{"scan": "Settings"}` | сонар по окнам со словом в названии |
| `{"click": [x, y]}` | клик (координаты брать из сонара!), границы проверяются |
| `{"open": "firefox"}` | детерминированный запуск с ожиданием и факт-проверкой |
| `{"wait": 10}` | пауза 1–30 с |
| `{"see": "..."}` | глаза (только если `AGENT_VISION` задан) |
| `{"done": "..."}` | задача завершена (только по факту) |

Рабочий цикл с GUI: `scan → click → scan (проверка)`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AGENT_MODEL` | `mybrain` | текстовый мозг |
| `AGENT_VISION` | *(пусто)* | зрительная модель; пусто = see выключен |
| `AGENT_UITREE` | `~/uitree.py` | путь к сонару |
| `SCAN=always` | выкл | автоскан после каждого действия |
| `EYE_SWAP=0` | выгружает | не выгружать мозг на время взгляда |
| `CONFIRM=1` | выкл | ручное одобрение каждого действия `[y/n]` |

## Диагностика

| Симптом | Причина и лечение |
|---|---|
| «сонар почти ничего не видит» | выключена accessibility → `gsettings set org.gnome.desktop.interface toolkit-accessibility true` + reboot |
| клик молчит/мимо | сеанс Wayland → «Ubuntu on Xorg» (шестерёнка на входе) |
| `open` пишет «НЕ УСТАНОВЛЕНА» | факт: программы нет → `snap list`, `ls /usr/share/applications` |
| `open` долго думает | норма: snap-программы просыпаются до 60 с, лаунчер ждёт |
| предупреждение про pyatspi при старте | `sudo apt install -y python3-pyatspi` |
| всё тормозит, машина виснет | RAM впритык: мозг поменьше (1.5b), `zram-config`, меньше окон |

## Миграция 4.1 → 4.2

Ничего сносить не надо: положите `agent_v4_2.py` рядом, `uitree.py` общий,
дневники подхватятся. Старую версию можно оставить как исторический артефакт.
